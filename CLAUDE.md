# Diwakar Mishra — Portfolio

Personal portfolio for a **software engineer** — B.Tech CSE-AI student (MAIT, 2024–2028), building full-stack apps and shipping them live. Built for an SDE internship / new-grad hunt covering **both big tech (Google, Amazon) and startups / small companies**.

That second audience is the one this site is actually for. At big tech the pipeline is resume screen → online assessment → interviews, and no portfolio helps with the OA — his LeetCode 1820 and 9.43 CGPA carry that. **At a startup the portfolio often IS the screen:** a founder or a two-person eng team reviewing 40 applicants will click the link and will play with the live demos, and they weight end-to-end product ownership far above contest rating. So the site optimises for *"this person can build a complete thing by themselves"*, and the design quality — near-worthless to an Amazon recruiter — is a real asset there, because it signals product judgment rather than ticket-closing.

**Repurposed from a Product Manager portfolio (Shweta Kumari's).** The entire Golden Hour design system, motion system, and section architecture were kept; all content, assets, and the Projects treatment were replaced. If something reads like it was written for a PM, it's a leftover — fix it rather than working around it.

This file is the **current-state** source of truth for design/technical decisions — what's true now, not how we got here (git history holds that). Follow it for all future work unless the user explicitly changes something. Add a one-line note under **Recent changes** for durable decisions; don't narrate.

## Stack

- Next.js (App Router) + TypeScript + Tailwind CSS v4 (`@theme inline`)

- Fonts via `next/font/google`

## Design system — "Golden Hour" (LOCKED)

**Site rhythm (revised):** vivid hero → light/cream (Projects, About) → warm sunset close (Contact). Originally planned as hero(vivid)→light→dark(Contact); Contact was explicitly reversed to close light/warm instead — a dark Contact would repeat the earlier failed dark-Projects treatment (see Rejected approaches). The hero opens the page in golden-hour light; Contact is the deliberate bookend that brings the light back down into a warm sunset, never dark. The "cohesive-yet-different" spine (type, motion, layout, per-project accent) holds regardless of section.

### Color tokens

CSS variables in `src/app/globals.css`, exposed as Tailwind utilities via `@theme inline`. `cream`/`ink` invert in the hero: `cream` becomes the text color, `ink` becomes the text-shadow tone that keeps it legible on the gradient.

| `ink`      | `#201E1B` | Primary text (calm) / hero text-shadow tone      |

### Typography

- **Display:** Bricolage Grotesque, weight 700–800, `--font-display-face` → `font-display`. Used for big uppercase display words (SOFTWARE ENGINEER, the DIWAKAR MISHRA eyebrow). Renders ~1.7x wider per character than Bebas Neue (the prior face) at the same size — re-measure text width (see Reusable technical rules) if the display face ever changes again.
- **Body:** Hanken Grotesk, weight 400/500/600, `--font-hanken-grotesk` → `font-body`. Two families only on the hero — don't add a third.

### Motion principles

- Ease-out only: `[0.16, 1, 0.3, 1]` cubic-bezier, everywhere. No bounce/flash. One deliberate, explicitly-requested exception: the project cards' screen-life gleam uses a local `EASE_IN_OUT` instead (see Projects below) — a "flows in and settles" feel was wanted specifically there. Don't spread ease-in-out elsewhere without the same kind of explicit ask.
- Everything respects `prefers-reduced-motion` via `usePrefersReducedMotion` (`src/lib/usePrefersReducedMotion.ts`) — a hydration-safe `useSyncExternalStore` hook, NOT motion's own `useReducedMotion` (resolves synchronously client-only, causes hydration mismatches). Same pattern for pointer-type detection: `useHasFinePointer` (`src/lib/useHasFinePointer.ts`).

## Copy & voice (LOCKED)

The site's prose is written **in Diwakar's own voice** — derived from his Starweave LinkedIn post, the Starweave About page, and his film reviews — but written for a reader who **arrives with zero context and about eight seconds.** Those two constraints fight each other, and the second one wins. A shipped draft got this backwards and had to be redone; the rules below are the correction.

**THE RULE THAT OVERRIDES EVERYTHING: every line must stand alone.** Would someone who has never heard of these projects understand this sentence by itself? If not it doesn't ship, however good the writing is.

Not a style preference — a hiring consequence. A reviewer meeting a cryptic line doesn't think "how thoughtful", they think *"I don't know what this person does"*, then *"can this person explain a system simply?"* That second question is a real negative signal for an engineer, since much of the job is explaining work to people who weren't in your head. **Clever writing that fails to communicate is worse than plain writing that succeeds** — plain writing doesn't make anyone question your communication.

Shipped, rejected, and not to be reintroduced in any form:

| Rejected line | Why it failed |
| --- | --- |
| *"I build things you can check, not things you have to trust."* (hero) | Check *what*? A riddle in the one slot that must say what he does. |
| *"I'd rather you check it than trust me."* (About heading) | Same riddle. |
| *"Tell me an influence I've missed."* (Contact close) | An influence *of what*. A Starweave-specific ask used as the site's closing CTA. |
| *"Elliott Smith sounds nothing like Fugazi…"* (Starweave opener) | Two obscure artists occupying the most valuable sentence on the flagship card. A reviewer can't evaluate "sounds nothing like" and won't go and listen. Excellent for his LinkedIn post, where readers opted into caring about indie music. Not portfolio copy. |
| *"Half the map goes quiet."* | What map, what switch. |
| *"cutting the mainstream titles that had crept in"* | Crept in from *where*? The reader was never told a list was being assembled. |

**Specificity only helps when the specific thing is legible to a stranger.** His *numbers* pass that test; his *artist names* do not. State the principle, not the private example — "influence isn't the same as sounding similar" does the Elliott Smith line's job for someone who has never heard either band.

**Where a claim needs a subject, name it.** Each About principle tile names its own project ("Every influence link in Starweave…", "Arthouse Atlas is 497 films…") so it survives being read out of order.

**Hero says what he builds; About says what he chooses to build.** Currently hero = *"I build complete products — data model, algorithm, interface."* (the end-to-end claim a small team is buying) and About heading = *"I pick problems that need more than a database."* (taste, and the thing that separates him from a wall of CRUD-app portfolios). Keep these two doing different jobs — an earlier pass had both saying "I build the whole thing" and the repetition wasted the more memorable line.

**No defensive phrasing.** A draft hero read *"…and I write the algorithms inside them myself"* — the "myself" was pre-empting an accusation nobody had made (that he only glues APIs together), which reads as insecurity. Same fix applied to the About body ("a scoring system I had to design myself" → "a scoring system that didn't exist off the shelf"). State the thing; don't argue with an imagined charge.

**The register to imitate is the Proof tile** — CGPA / LeetCode rating / GRiD / CodeX. Four hard facts, no adjectives, nothing to decode. It is the most effective block on the site precisely *because* it doesn't try.

Style mechanics, still his: sentences under ~12 words; prefer a fragment to a subordinate clause; state a number then stop, never characterise it ("impressive", "significant"); no marketing register ("platform", "accelerator", "seamless").

**Register map** — density is placed deliberately, not spread evenly. Everything dense reads as a spec sheet; everything warm reads as fluff:

| Section | Leads with |
| --- | --- |
| Hero | voice + one idea |
| Projects intro | curiosity |
| Project cards | dense technical detail — **all hard numbers live here** |
| About statement | the insight connecting the work |
| About principles | one human-readable idea per project, ~18 words, no numbers |
| About human note | warmth only — the deliberate breath in the page |
| Contact | plain and professional |

**Accuracy constraints.** Every claim traces to his résumé; invent nothing. No adoption/traffic/stars claims — there are none. Deltas keep their baseline visible ("70% to 11%", never "84% better"). Provenance is phrased as *where the claim came from*, because 908 of 1,053 edges cite a named source — "every edge cites a source" would be false. Canonical Starweave figures are **297 / 1,053 / 908 / 562 / 30**; his LinkedIn post's 293 / 1,041 / 887 / 544 are stale and must never be used.

**Still to sharpen:** CareerSaarthi's card credits "a team" generically. Swap in his specific personal contribution when he supplies it — "I built X" is far stronger, and "what did *you* do?" is a guaranteed interview question. The **70% → 11%** Dijkstra result is deliberately absent from the site until he supplies the methodology; writing a number that can't be defended is the exact failure this copy pass exists to prevent.

## Current architecture

### Hero (`Hero.tsx`, `GoldenHourSky.tsx`, `HeroEmbers.tsx`)

- **Sky:** full-bleed vivid sunset gradient (twilight→amber→coral), gold sun-glow upper-right, drifts slowly, disabled under reduced motion. Tunables at top of `GoldenHourSky.tsx`. Fades to cream at the bottom for a clean handoff into Projects.
- **Text:** hero text is cream-on-gradient; carries `.hero-text-glow` (body-scale text) or `.hero-heading-shadow` (the big display words — a single zero-offset glow, not the two-layer offset shadow, which looks dated at display scale).
- **Cut-out figure — OPTIONAL, currently OFF.** Gated behind `PORTRAIT_SRC` at the top of `Hero.tsx` (`null` = off). The previous owner's photo was removed and no replacement has been supplied yet. While it's null the hero runs as a **type-only composition**: the desktop text column widens to `left-[6%] right-[6%]` instead of a left-aligned `w-[64%]`, the mobile column switches from top-aligned (`pt-6`, figure pinned bottom via `mt-auto`) to vertically centered (`justify-center pb-16`), and the figure's grounding glow is suppressed with it (on its own it's just an unexplained warm smudge). Set `PORTRAIT_SRC` to a real transparent PNG in `/public` and the original composition returns unchanged. When on: bottom-right, `right-[5%]`, `h-[70vh] lg:h-[74vh]` (mobile: `h-[34vh] max-h-72`). Warm-graded via 3 masked layers in the local `CutoutFigure` component (base filter, directional warm/cool wash, screen-blend rim-light) — tunable via `CUTOUT_GRADE_STRENGTH`. The grade assumes light from the upper-right, so a replacement portrait should face slightly LEFT. Z-order back-to-front within the hero: embers (`z-5`) → ambient ground-glow behind her feet (`z-9`) → text column (`z-10`) → figure (`z-20`). The site-wide cursor (see below) sits in its own `z-[9999]` fixed layer above all of this, not part of the hero's local stack.
- **Type/figure overlap (only when `PORTRAIT_SRC` is set):** eyebrow+headline+tagline form one left-aligned column, figure sits in front, so only the last letter of "ENGINEER" tucks behind the shoulder. Desktop stage capped at `max-w-[1600px]` to keep this overlap correct across realistic widths (verified at 1024/1280/1440/1920px) — don't re-derive the cap; re-verify at those widths if the layout changes.
- **Responsive:** two structurally different layouts — plain stacked flow on mobile (no overlap), absolutely-positioned composition on `sm:` and up. Don't force one system to cover both.
- **Ambient effects:** drifting cream/white embers (canvas, `HeroEmbers.tsx`), hero-local only. The cursor effect used to live here too (bounded to the hero) but is now a site-wide layer — see below.
- **Nav:** includes a minimal scroll-spy that highlights "Projects" while that section is in view.

### Favicon (`src/app/icon.svg`)

A "dm" monogram in cream on the Golden Hour sunset gradient (gold→amber→coral), matching the hero nav mark. Replaced the stock `favicon.ico`, which was byte-identical to the Next.js default and showed the framework's own logo in the browser tab. **The letterforms are drawn as paths, not `<text>`** — an SVG favicon rasterises at 16px in a context with no guarantee about available fonts, and a missing face would silently fall back or render nothing. Verified legible at 16/32/64/110px. `favicon.ico` was deleted, so `/favicon.ico` now 404s and browsers use the emitted `<link rel="icon" href="/icon.svg">` instead; that's expected, not a bug.

### Site-wide ambient background (`AmbientBackground.tsx`)

Mounted once in `layout.tsx`, `position: fixed; -z-10; inset-0`, behind all content:

1. **Aurora** (the star) — 3 large, heavily-blurred (90px) color blooms (amber, coral, fainter twilight), each drifting independently (`.aurora-drift-a/b/c` in `globals.css`, different durations so they never sync).
2. **Embers** — 5 small gold particles with a glow halo, drifting upward, a minor accent over the aurora.
3. **Grain** — static SVG-noise texture.

All tunable from constants at the top of the file. The hero is excluded (keeps its own opaque sky). Any calm section must have no opaque section-level background to inherit this layer; a dark section can opt out with its own opaque background (like the hero does).

### Site-wide custom cursor (`CursorFollow.tsx`)

Mounted once in `layout.tsx` (last child of `body`, after `{children}`), `position: fixed; z-[9999]` — same "mount once at the layout level" pattern as `AmbientBackground`. Originally hero-only (bounded to `heroRef`); moved site-wide because it needs to read on every section, hero AND the light cream sections alike, not just the hero.

- **The star IS the cursor**, not a trailing effect: the real system cursor is hidden globally via `@media (pointer: fine) { * { cursor: none !important; } }` in `globals.css` (`!important` and `*` are both load-bearing — Tailwind's preflight sets `cursor: pointer` directly on buttons/links, which would otherwise override a plain inherited `cursor: none` on `body`). An inlined four-point SVG star (coral `#E4674F` — chosen because gold/white vanish on the cream sections) tracks the pointer with a stiff, barely-there spring (must read as the actual cursor, not a laggy sparkle) and scales up ~1.35x over links/buttons/inputs (detected via `e.target.closest(...)` on a site-wide `mousemove` listener).
- **A soft warm light-bloom trails behind it** (gold→amber radial gradient, lower stiffness spring than the star for a gentle comet lag) — brought back at a moderate level after a prior pass over-corrected a "too intense" complaint into removing it entirely. Plain alpha compositing, no `mix-blend-mode` — the original hero-only version used `mix-blend-mode: screen` against the vivid gradient, but screen-blending a warm colour onto near-white cream washes it out almost entirely; plain alpha (the same technique the aurora blooms use) is what actually stays visible on both backgrounds.
- Desktop/fine-pointer only (`(pointer: fine)`, same hydration-safe `useSyncExternalStore` check as `useHasFinePointer`); returns `null` on touch/coarse-pointer devices, restoring the normal system cursor there. `prefers-reduced-motion`: position tracks 1:1 on both the star and the glow (springs bypassed entirely, not just dampened) and hover-scale snaps instead of easing; the show/hide opacity fade is left springy either way since it's a discrete state change, not continuous motion.
- All tunable at the top of the file: star size/color/opacity/hover-scale/self-glow-blur/spring, glow radius/opacity/color/spring.
- **Gotcha — a fresh `.next` build cache can silently serve stale CSS.** After adding the `cursor: none` rule, `document.styleSheets` genuinely didn't contain it in a running dev session even after editing the file — not a code bug, just a stale cache; `rm -rf .next` and restarting picked it up immediately. If a CSS-only change ever seems to have "no effect" despite the source being correct, check the compiled stylesheet directly (iterate `document.styleSheets`) before assuming the code is wrong.

### Projects (`Projects.tsx`, `ProjectCard.tsx`)

Spine (type, cream base, layout, motion, structure) is identical across all 3 cards; only the accent color differs. Current assignments: Starweave → purple `#8B6FC9`, Arthouse Atlas → coral `#E4674F`, CareerSaarthi → twilight `#6B8CAE`.

All three projects are real, publicly reachable web apps, but that is deliberately NOT the section's argument (see the one-mention rule above) — the argument is the engineering behind each one. Every card links out to the running app and its source, and each carries its build `year`.

- **Panels:** each project in its own `rounded-3xl` panel, soft shadow, background = `linear-gradient(135deg, rgba(accent, 0.21), rgba(accent, 0.1))` layered over an explicit `var(--color-cream)` backing (blocks the aurora from bleeding through and muddying the accent — see Reusable technical rules). Stat number + link use a `darken()`-ed (32%) version of the accent for text contrast; panels use the raw accent.
- **Plain framed screenshots — no fake browser chrome, and no phones.** Each shot sits in `AppScreenshot`: `rounded-xl`, hairline ring, drop shadow that deepens on hover. That's it. The portrait-phone PNGs of the previous build were wrong for desktop web apps; a *mock browser window* (dark title bar, traffic lights, address pill showing the live domain) was also tried and **removed**, for three reasons worth not rediscovering:
  1. **Double header.** All three apps have their own nav bar at the top of the screenshot, so the fake chrome stacked a second header above a real one.
  2. **A frame must read as not-content.** The chrome was `#302C28` and all three apps are dark, so it merged into them rather than framing them.
  3. **The address pill featured a `*.vercel.app` subdomain.** A custom domain would be worth showing; a free subdomain in large type just draws the eye to it.
  The rounded corners and shadow are already enough to read as "a screen", and the "this is really deployed" point is carried by the `Live demo` link plus one mention in the Projects intro — it does not need a third restatement in fake pixels.
- **Screenshots:** captured with Playwright at 1440x900 @2x, downscaled to 1600x1000, so **one shared `aspect-[16/10]`** covers every image (`SHOT_ASPECT`) — no per-image aspect lock needed, unlike the old phone PNGs which each had their own dimensions. `object-cover object-top` so the nav/headline of each app is always what's visible. To re-shoot: dismiss any onboarding modal and let canvas/force-graph content settle (Starweave's graph needs ~9s to converge) before capturing.
- **Signature interaction (all 3 cards):** desktop/fine-pointer-only 3D cursor-tilt (damped `useSpring` rotateX/rotateY, capped at 6°, resets on pointer-leave) + layered depth (the frame sits on a real forward Z-plane via `transformStyle: preserve-3d`, floats further on hover) + stat count-up. All tunables at top of `ProjectCard.tsx`.
- **Stats carry their own baselines.** Every headline number is real and checkable, and where a claim is a delta the baseline is stated rather than implied ("from 70% to 11%", never "84% better"). `StatCounter` handles thousands separators — it parses digits only and re-applies grouping on output, because `parseInt("1,053")` silently stops at the comma and counts up to 1.
- **Links go to real destinations:** every card has "Live demo" + "Source", both external. The previous build pointed a single "Read more" at `/projects/[slug]`, a route that never existed — all three cards 404'd. For shipped public apps the live demo *is* the case study; don't reintroduce a stub case-study route unless there's real writing to put in it.
- **Replay-on-re-entry (shared by every card):** `useReplayOnReentry` (`src/lib/useReplayOnReentry.ts`) returns one incrementing `playToken` per card — 0 until it first scrolls comfortably into view (`amount: 0.5`), then +1 each time it re-enters after having FULLY left the viewport since the last play (a second, `amount: 0` check for "has it completely left" — re-arms it; prevents twitchy re-triggering from hovering near the edge). Works in either scroll direction. Never advances past 0 when `reduced` is true. The stat count-up restarts from 0 on every increment (`useEffect` keyed on `playToken`), and the gleam replays with it since both share the one token.
- **Screen-life gleam:** a single light sweep across the frame (2.4s, 0.15s delay), replaying on the shared token. Uses a dedicated `EASE_IN_OUT` cubic-bezier local to `ProjectCard.tsx` — a deliberate, flagged exception to the site's "ease-out curves only" rule (see Motion principles). **This replaced a richer three-beat overlay** (gleam → hero-number glow bloom → gold sparkle) whose glow and sparkle were pinned to hand-measured percentage coordinates over each phone's own "hero number." Desktop web-app screenshots have no single hero numeral to bloom behind, so those two beats had nothing to anchor to and were dropped; the gleam generalizes because it sweeps the whole frame and needs no per-image measurement. Don't reintroduce coordinate-pinned overlay beats without an actual anchor to pin them to.

### About (`About.tsx`) — bento grid

Sits between Projects and Contact, on the shared cream/aurora background (no opaque section background — the site-wide aurora shows through and is meant to blend into the tiles' warm tints, unlike Projects' panels which deliberately block it). Deliberately carries NO photo — the hero cut-out already owns the face — so presence comes entirely from bold type, tile composition, and warm tinted depth, not animation or imagery. Superseded an earlier stacked/editorial layout (asymmetric statement + "How I work" row + footer-style credibility block) that read too much like a long scroll; the bento grid's whole point is that everything fits in roughly one view.

- **Grid:** 12-col CSS grid, `gap-[15px]`, `max-w-[1210px]` mx-auto. Tiles get their span via plain Tailwind `col-span-*`/`row-span-*` utilities gated behind a custom `min-[820px]:` breakpoint (below it every tile is `col-span-12`, full-width, stacking in source order — Statement → Proof → 3 principles → Toolkit → Human note). Above 820px: Statement (`col-span-8 row-span-2`) + Proof (`col-span-4 row-span-2`) fill row 1–2; three principle tiles (`col-span-4` each) auto-flow into row 3; Toolkit (`col-span-8`) + Human note (`col-span-4`) auto-flow into row 4 — no explicit `grid-row` needed, the spans alone make the auto-placement land correctly.
- **Tile shell (`.bento-tile` in `globals.css`):** shared by every tile — 26px radius, hairline border (defaults to `rgba(255,255,255,.55)`, overridden per themed tile), a layered shadow (inset top highlight + soft warm drop shadow), a `::before` top-sheen (top 40%, white-to-transparent) for a lit/tactile feel, and a fine-pointer-only hover lift (`translateY(-2px)` + deeper shadow, via `@media (hover: hover)`, not gated on reduced-motion since it's a discrete hover affordance like Contact's pill lift). Only each tile's own background gradient + border color vary, passed as plain string constants (same pattern as `ProjectCard`'s `panelTint`) — all deliberately warm (amber/coral/rose/terracotta/gold), no cool blue/purple, so the grid reads as one golden-hour family; separation comes from tint shade + border + depth, not hue temperature.
- **Content:** Statement tile (the anchor — "I'd rather you **check it** than trust me.", `clamp(2.1rem,3.9vw,3.7rem)` Bricolage, with degree/class-of-2028/Delhi and the weighting through-line beneath) + Proof tile (**4** stacked stat/caption pairs: CGPA, LeetCode rating, Flipkart GRiD, CodeX) fill the top; 3 principle tiles (accent dash + bold title + one-liner) fill the middle — **one per project** ("Let people check it", "Curation is subtraction", "Plan for the API failing"), each ~18 words with no numbers in them (the numbers live in the project cards, and a denser draft pushed this row from 3 lines to 7 at 1024px); Toolkit (skill pills, same tactile-pill construction as Contact's link chips) + a deliberately small/quiet Human note (gold sparkle + one line) close it out.
- **Motion — real bug first hit here (and now fixed site-wide, see Reusable technical rules):** each tile is `motion.div` with `initial="hidden"` + `whileInView="visible"` (gentle per-tile stagger via incrementing `delay`). Tiles below the fold that never intersect the viewport got stuck at `opacity:0` even under `prefers-reduced-motion` — because `usePrefersReducedMotion()` reports `false` on the very first client render by design, and Framer Motion's `initial` pose, once resolved at that first (pre-correction) render, doesn't retroactively update just because the `variants` object reference changes later for a component that's still sitting in its untriggered `whileInView` state. Fixed by adding `animate={reduced ? "visible" : undefined}` — `animate` outranks `whileInView` in Framer's priority order, so it forces every tile to its final visible state the instant `reduced` corrects to `true`, regardless of scroll position or intersection. This is the Framer-Motion analog of the `useState`/`useSpring` "initial value only applies once" trap already in Reusable technical rules below — same root cause, different API.
- **Whitespace gotcha reused from the previous build:** the statement's coral `<span>check it</span>` needs `{" "}` explicitly on both sides — see Reusable technical rules.

### Contact — the closing section (`Contact.tsx`)

Currently the last section on the page (`About` will be inserted between Projects and this later — `page.tsx` has a placeholder comment marking the spot). This is the visual bookend to the hero: the hero opens the page in vivid golden-hour light, this section brings it back down into a warm sunset close. Light and warm throughout — never dark, unlike the originally-planned dark Contact (see Site rhythm above and Rejected approaches).

- **Background:** its own opaque vertical gradient (`SUNSET_GRADIENT`, `linear-gradient(to bottom, #F4EEE4 0%, #F3DDBE 55%, #EFBEA0 100%)`) — cream at the top continuing from whatever precedes it, deepening into a pale warm amber/coral "bright horizon" at the bottom. Deliberately much paler than the hero's full-saturation Vivid Sky. Like the hero, this section opts OUT of the shared ambient aurora (`AmbientBackground.tsx`) by keeping its own opaque background — aurora is for the in-between calm sections; hero and this closing section are the two dedicated-atmosphere bookends.
- **Living sunset:** two large, heavily-blurred warm blooms (amber, coral — `.sunset-bloom-drift-a/b` in `globals.css`) plus a low "sun" glow that drifts side to side and pulses in size/opacity (`.sunset-glow-drift`), all layered over the static gradient. Same transform-only drift technique as the site-wide aurora (translate + scale, GPU-friendly), tuned warmer AND — after a first pass that matched the aurora's own subtlety (3–4% translate, 16–20s) and read as static — deliberately more pronounced: ~9–12% translate, scale swinging ~0.86–1.28, opacity swinging ~0.45–1 on the sun-glow, 12/14/16s durations. This section is meant to be clearly noticed, unlike the aurora's "felt, not noticed" bar. Per-element opacity/size are tunables in `Contact.tsx` (`SUN_GLOW_*`, `SUNSET_BLOOM_*`, raised from their first-pass values too); durations/ranges live in the `globals.css` keyframes alongside the aurora's. Verified by sampling computed transforms over ~8s (not a still screenshot — confirmed tx/ty/scale/opacity all swing substantially) and by screenshotting three points across a cycle — text stays fully legible throughout. **Gotcha:** the sun-glow's centering (`left: 50%` + `translateX(-50%)`) is baked into its own keyframe rather than a separate static transform — under `prefers-reduced-motion`, disabling the animation would lose that centering entirely unless the class ALSO sets a static `transform: translateX(-50%)` fallback outside the keyframe (it does — don't remove it if this ever gets refactored).
- **Content, centered, generous spacing:** headline ("Tell me an influence I’ve missed.", ink, big Bricolage — adapted from the close of his own Starweave LinkedIn post, so it's a real invitation rather than a CTA cliché) → sub-line (muted, Hanken) → email as the primary CTA (`diwakarmishraemail@gmail.com`, `mailto:`) → LinkedIn/GitHub/LeetCode/Download-CV as pill chips (LeetCode added — a real credibility signal for an SDE hunt; its icon is a clean `< >` brackets glyph, NOT a traced LeetCode logo, which turns to mush at 16px and read as a vague arrow).
  - **Email:** a deep warm brown (`EMAIL_COLOR = "#7A2E1E"`) at rest, shifting to coral (`EMAIL_HOVER_COLOR`, matches `--color-coral`) on hover, plus a coral underline draw-in and a soft coral `text-shadow` bloom. Colors are set as `--email-color`/`--email-hover-color` CSS custom properties (consumed by `.email-cta`/`.email-cta:hover` in `globals.css`), NOT plain inline styles — an inline `style.color` can't respond to `:hover`, but a custom property consumed by a stylesheet rule can. The underline (`bg-current`) and hover glow automatically track whichever color is live.
  - **Links:** tactile pill chips (`LINK_PILL_CLASS` in `Contact.tsx`) — semi-transparent white over the sunset, a warm border derived from the same brown as the email, `backdrop-blur-sm`, small `currentColor` icon + label. Lift (`-translate-y-0.5`) + more-opaque background + soft warm shadow on hover.
- **Email wrapping gotcha:** a long email with no spaces is one unbreakable "word" — `break-all`/`break-words` picks an arbitrary character boundary on narrow screens (e.g. split "gmail.co" / "m"). Fixed by splitting the string into local-part/domain in JS and inserting a `<wbr />` between them, so the browser prefers breaking at the `@` and only falls back further if it still doesn't fit.
- **Footer bar:** slim, muted, static (not part of the scroll-reveal choreography — deliberately, per brief: "functional baseline, not a design moment"). © line (Diwakar Mishra), an optional repeated nav (Projects · About · Contact — all three anchors now resolve, since About shipped), and "Back to top ↑" (`href="#top"`, matching `<main id="top">` in `page.tsx`; works via the site-wide `scroll-behavior: smooth`, no JS needed).
- **Motion:** headline/sub-line/email/links reveal once on scroll-in (fade + rise, same `reveal()` shape as `Projects.tsx` — plain `whileInView`/`once: true`, NOT the replay-on-re-entry hook, since a one-time arrival moment doesn't need to replay every time you scroll past the footer and back). Background drift is separate and continuous (see Living sunset above), gated on the same `prefers-reduced-motion` check.

## Reusable technical rules

- **A broken primary CTA costs more than any amount of bad copy.** `Download CV` pointed at a PDF that was never in `public/`, so the one button a recruiter actually wants returned a 404 — on a site whose whole argument is that its author ships things that work. From a reviewer's chair that isn't a missing file, it reads as *this person doesn't check their own work*. **Enumerate every `href` and assert it resolves** as a standing verification gate. When an asset is missing, remove the control rather than leave it broken (a missing button costs almost nothing) and keep the removal reversible with a comment naming the exact expected path.
- **Undated work reads as "unknown", and reviewers resolve unknowns pessimistically.** Nothing carried a year, so there was no way to tell whether three apps were built in one year or across three — and recency is the main signal a student portfolio has. Each card now carries a `year`. Deliberately per-card rather than a prose line like "all built this past year", which goes stale the moment the year turns; same reason nothing hardcodes a year of study, since `class of 2028` never does.

- **Measuring rendered text width:** use a DOM `Range` (`range.selectNodeContents(el)`) over the text node, not `el.getBoundingClientRect()` — a flex child without `items-start` stretches to fill its container, so its own bounding box isn't the actual glyph extent.
- **Absolutely-positioned children ignore a parent's padding** as an inset — use explicit `left-*`/`right-*`, not `left-0`/`right-0`, if the parent has padding.
- **A `position: fixed` background layer is invisible behind any section's own opaque background** — sections must have no opaque `background-color` to let it show through; this is normal CSS painting, not a stacking bug.
- **A semi-transparent panel over a transparent section picks up whatever is behind it.** If it needs a consistent look regardless of what's behind (e.g. the aurora), give it an explicit opaque backing color in the same `background` shorthand, not just its own tint alone.
- **`useState`/`useSpring` initial values only apply on the very first render.** Never seed one from `usePrefersReducedMotion()`'s value directly (`useState(reduced ? a : b)`) — it reports `false` on first paint by design and only corrects after hydration, so the initializer gets stuck on the wrong branch. Compute the reduced-motion value at render time instead, or correct it via a `useEffect` keyed on `reduced`.
- **Percentage-positioned overlay children need their image wrapper's aspect ratio locked to the source asset's exact ratio** (`aspect-[w/h]`) — otherwise `object-contain` letterboxes differently at every breakpoint and every percentage drifts.
- **Verifying "is this visible enough" requires actually looking** (screenshot/pixel sampling), not reasoning about opacity math. A layer can be technically non-zero but practically imperceptible; when that happens, suspect the *technique* (e.g. many small faint particles vs. a few large color blooms), not just the opacity value.
- **Playwright round-trip latency (evaluate calls, console.log, `scrollIntoViewIfNeeded`) can itself eat as much time as a short animation**, causing a naive "scroll → wait → screenshot" test to miss the whole window and look broken. Sample `getComputedStyle(...)` inside a single in-page `requestAnimationFrame` loop instead for ground truth.
- **Next dev's image-optimizer cache (`.next/dev/cache/images`) doesn't reliably invalidate when a `public/` file is swapped under a running server** — delete that directory and restart if a replaced image isn't showing up.
- **A JSXText child's leading/trailing whitespace is trimmed even when there's no line break** — whitespace sitting at the very start/end of a text node (i.e. touching a tag boundary) is unsafe, not just whitespace that crosses a line break. `<span>foo</span> bar` can silently render as "foobar." Wrap the space in its own expression container instead — `<span>foo</span>{" "}bar` — on every side of the tag that needs one.
- **A Framer Motion element using `initial`/`whileInView` + a `variants` object built from `usePrefersReducedMotion()` can get stuck invisible.** The hook reports `false` on the very first client render by design (see the `useState`/`useSpring` rule above), so `initial="hidden"` resolves against the WRONG (not-yet-reduced) variants at that first render. For an element that never satisfies `whileInView` (e.g. it's below the fold and the page never scrolls that far), Framer doesn't retroactively re-apply `hidden` once `variants` updates to the corrected (reduced) values — it just stays at whatever pose it first resolved to, i.e. genuinely invisible, even though `reduced` is now `true` and hidden/visible are supposed to be identical. Fix: add `animate={reduced ? "visible" : undefined}` — `animate` outranks `whileInView` in Framer's priority order, so it force-corrects the pose the instant `reduced` flips true, independent of scroll position. Same root cause as the `useState`/`useSpring` rule (a value that's wrong on first paint and only corrects after hydration), different API surface. **This applies to EVERY such element, not just the one where the bug is first noticed** — it was originally patched only on About's tiles, leaving Projects (11 elements), Contact (4), and About's own section label silently broken for reduced-motion users. When adding any new `initial`/`whileInView` + reduced-variants element, add the `animate` override in the same edit, and verify by enumerating computed opacity under an emulated `prefers-reduced-motion` rather than by eye (below-the-fold elements are exactly the ones that break, and they're the ones you won't look at).
- **Don't put an animated number on a shared line with anything else.** A count-up from 0 to "1,053" takes the glyph run from ~40px to ~151px; anything sharing its row gets squeezed and can wrap, changing the container's height mid-animation (this shipped, and read as the card "jumping"). Proportional digits make it worse — even at a constant digit count, "1,003" measured 151px against "1,013" at 132px, so the neighbour wrapped and unwrapped repeatedly on the way up. The fix that shipped is **structural: stack the number above its label** so it's alone on its line with nothing to push, which also gives the label the full column width and keeps it on one line. Reserving the final width instead (an invisible sizer holding the final string, live value stacked over it in one `inline-grid` cell) does stop the reflow, but it forces the neighbour to live at the number's *widest* size permanently — which just made the two-line label permanent rather than intermittent. Prefer the structural fix; reach for the sizer only when something genuinely must sit beside a counter. Either way keep `tabular-nums`, so digits don't shimmy internally as they change.
- **Verify layout stability by sampling, not by screenshot.** Read `getBoundingClientRect().height` in a single in-page `requestAnimationFrame` loop across the whole animation and assert one distinct value. A before/after screenshot pair cannot catch a transient mid-count reflow — both endpoints looked fine while the middle was visibly jumping.
- **To force a `motion` animation to replay cleanly (not just re-trigger a boolean prop), remount via a `key` that increments each time it should play**, rather than toggling `animate` between two states — a fresh mount always starts from `initial` with no risk of catching a previous play's reverse-transition mid-flight. Relatedly: an effect shaped like `if (someDependency) { setSomeState(literalValue); }` — mirroring one signal directly into another piece of state — reliably trips the `react-hooks/set-state-in-effect` lint rule even when it's legitimate (e.g. resetting on exit before an unrelated later re-arm); restructuring so the state update is a functional counter increment (`setState(n => n + 1)`) in only one conditional branch, with other branches only touching refs, avoids it.

## Working agreement

- This file is the source of truth. Reuse these tokens/patterns for new sections; don't introduce new ones without reason.
- Ritual scales with novelty: reusing an existing pattern (new project card, About/Contact using locked tokens) = build, self-check in browser, one-line note, minimal ceremony. Establishing a genuinely NEW pattern = verify properly and flag it. Mechanical tweaks (spacing, copy, constants) = no ritual.
- Self-verify by default: check your own work in the browser for visual/behavioral changes. Don't ask permission first and don't proactively share screenshots unless asked.
- Maintain this file yourself: add a one-line note under **Recent changes** for durable decisions (new token, convention, or shipped section/pattern); update the relevant architecture section above if something changed structurally. Skip logging for small tweaks.

## Verification discipline

- Verify once, visually/behaviorally, after finishing a section or a change flagged as visual/animation work — then conclude.
- Small mechanical edits (spacing, copy, color, constants, renames) need no screenshots/test scripts unless something could plausibly break.
- Typecheck (`tsc --noEmit`) + lint are the primary correctness gate for logic — don't add ad-hoc test scripts beyond that unless asked.
- If a verification result looks wrong, suspect the test/measurement method first, not the code. Don't spiral into repeated re-testing — state the uncertainty in one line and move on.
- One clean verification pass beats exhaustive re-confirmation.
