# Shweta Kumari — Portfolio

Personal portfolio for a Product Manager with a product-design background — built for a PM job hunt. Must read as passionate, design-literate, and premium: memorable but credible to hiring managers.

This file is the **current-state** source of truth for design/technical decisions — what's true now, not how we got here (git history holds that). Follow it for all future work unless the user explicitly changes something. Add a one-line note under **Recent changes** for durable decisions; don't narrate.

## Stack

- Next.js (App Router) + TypeScript + Tailwind CSS v4 (`@theme inline`)
- `motion` (successor to `framer-motion`) — import from `motion/react`
- Fonts via `next/font/google`

## Design system — "Golden Hour" (LOCKED)

**Site rhythm (revised):** vivid hero → light/cream (Projects, About) → warm sunset close (Contact). Originally planned as hero(vivid)→light→dark(Contact); Contact was explicitly reversed to close light/warm instead — a dark Contact would repeat the earlier failed dark-Projects treatment (see Rejected approaches). The hero opens the page in golden-hour light; Contact is the deliberate bookend that brings the light back down into a warm sunset, never dark. The "cohesive-yet-different" spine (type, motion, layout, per-project accent) holds regardless of section.

### Typography

- **Display:** Bricolage Grotesque, weight 700–800, `--font-display-face` → `font-display`. Used for big uppercase display words (PRODUCT MANAGER, the SHWETA KUMARI eyebrow). Renders ~1.7x wider per character than Bebas Neue (the prior face) at the same size — re-measure text width (see Reusable technical rules) if the display face ever changes again.
- **Body:** Hanken Grotesk, weight 400/500/600, `--font-hanken-grotesk` → `font-body`. Two families only on the hero — don't add a third.

### Motion principles

- Ease-out only: `[0.16, 1, 0.3, 1]` cubic-bezier, everywhere. No bounce/flash. One deliberate, explicitly-requested exception: the AI Resume screen-life overlay's gleam/glow/sparkle use a local `EASE_IN_OUT` instead (see Projects below) — a "flows in and settles" feel was wanted specifically there. Don't spread ease-in-out elsewhere without the same kind of explicit ask.
- Everything respects `prefers-reduced-motion` via `usePrefersReducedMotion` (`src/lib/usePrefersReducedMotion.ts`) — a hydration-safe `useSyncExternalStore` hook, NOT motion's own `useReducedMotion` (resolves synchronously client-only, causes hydration mismatches). Same pattern for pointer-type detection: `useHasFinePointer` (`src/lib/useHasFinePointer.ts`).

## Current architecture

### Hero (`Hero.tsx`, `GoldenHourSky.tsx`, `HeroEmbers.tsx`)

- **Sky:** full-bleed vivid sunset gradient (twilight→amber→coral), gold sun-glow upper-right, drifts slowly, disabled under reduced motion. Tunables at top of `GoldenHourSky.tsx`. Fades to cream at the bottom for a clean handoff into Projects.
- **Text:** hero text is cream-on-gradient; carries `.hero-text-glow` (body-scale text) or `.hero-heading-shadow` (the big display words — a single zero-offset glow, not the two-layer offset shadow, which looks dated at display scale).
- **Cut-out figure:** `/public/portrait-cutout.png` (transparent PNG) stands directly in the scene, bottom-right, `right-[5%]`, `h-[70vh] lg:h-[74vh]` (mobile: `h-[34vh] max-h-72`) — sized down from the original `h-[78vh] lg:h-[82vh]`/`h-[38vh] max-h-80` on request. Warm-graded via 3 masked layers in the local `CutoutFigure` component (base filter, directional warm/cool wash, screen-blend rim-light) — tunable via `CUTOUT_GRADE_STRENGTH`. Z-order back-to-front within the hero: embers (`z-5`) → ambient ground-glow behind her feet (`z-9`) → text column (`z-10`) → figure (`z-20`). The site-wide cursor (see below) sits in its own `z-[9999]` fixed layer above all of this, not part of the hero's local stack.
- **Type/figure overlap:** eyebrow+headline+tagline form one left-aligned column, figure sits in front, so only the last letter of "MANAGER" tucks behind her. Desktop stage capped at `max-w-[1600px]` to keep this overlap correct across realistic widths (verified at 1024/1280/1440/1920px) — don't re-derive the cap; re-verify at those widths if the layout changes.
- **Responsive:** two structurally different layouts — plain stacked flow on mobile (no overlap), absolutely-positioned composition on `sm:` and up. Don't force one system to cover both.
- **Ambient effects:** drifting cream/white embers (canvas, `HeroEmbers.tsx`), hero-local only. The cursor effect used to live here too (bounded to the hero) but is now a site-wide layer — see below.
- **Nav:** includes a minimal scroll-spy that highlights "Projects" while that section is in view.

### Site-wide ambient background (`AmbientBackground.tsx`)

Mounted once in `layout.tsx`, `position: fixed; -z-10; inset-0`, behind all content:

1. **Aurora** (the star) — 3 large, heavily-blurred (90px) color blooms (amber, coral, fainter twilight), each drifting independently (`.aurora-drift-a/b/c` in `globals.css`, different durations so they never sync).
2. **Embers** — 5 small gold particles with a glow halo, drifting upward, a minor accent over the aurora.
3. **Grain** — static SVG-noise texture.

All tunable from constants at the top of the file. The hero is excluded (keeps its own opaque sky). Any calm section must have no opaque section-level background to inherit this layer; a dark section can opt out with its own opaque background (like the hero does).

### Site-wide custom cursor (`CursorFollow.tsx`)

Mounted once in `layout.tsx` (last child of `body`, after `{children}`), `position: fixed; z-[9999]` — same "mount once at the layout level" pattern as `AmbientBackground`. Originally hero-only (bounded to `heroRef`); moved site-wide because it needs to read on every section, hero AND the light cream sections alike, not just the hero.

- **The star IS the cursor**, not a trailing effect: the real system cursor is hidden globally via `@media (pointer: fine) { * { cursor: none !important; } }` in `globals.css` (`!important` and `*` are both load-bearing — Tailwind's preflight sets `cursor: pointer` directly on buttons/links, which would otherwise override a plain inherited `cursor: none` on `body`). An inlined four-point SVG star (coral `#E4674F` — chosen because gold/white vanish on the cream sections) tracks the pointer with a stiff, barely-there spring (must read as the actual cursor, not a laggy sparkle) and scales up ~1.35x over links/buttons/inputs (detected via `e.target.closest(...)` on a site-wide `mousemove` listener).
- **A soft warm light-bloom trails behind it** (gold→amber radial gradient, lower stiffness spring than the star for a gentle comet lag) — brought back at a moderate level after a prior pass over-corrected a "too intense" complaint into removing it entirely. Plain alpha compositing, no `mix-blend-mode` — the original hero-only version used `mix-blend-mode: screen` against the vivid gradient, but screen-blending a warm colour onto near-white cream washes it out almost entirely; plain alpha (the same technique the aurora blooms use) is what actually stays visible on both backgrounds.
- Desktop/fine-pointer only (`(pointer: fine)`, same hydration-safe `useSyncExternalStore` check as `useHasFinePointer`); returns `null` on touch/coarse-pointer devices, restoring the normal system cursor there. `prefers-reduced-motion`: position tracks 1:1 on both the star and the glow (springs bypassed entirely, not just dampened) and hover-scale snaps instead of easing; the show/hide opacity fade is left springy either way since it's a discrete state change, not continuous motion.
- All tunable at the top of the file: star size/color/opacity/hover-scale/self-glow-blur/spring, glow radius/opacity/color/spring.
- **Gotcha — a fresh `.next` build cache can silently serve stale CSS.** After adding the `cursor: none` rule, `document.styleSheets` genuinely didn't contain it in a running dev session even after editing the file — not a code bug, just a stale cache; `rm -rf .next` and restarting picked it up immediately. If a CSS-only change ever seems to have "no effect" despite the source being correct, check the compiled stylesheet directly (iterate `document.styleSheets`) before assuming the code is wrong.

### Projects (`Projects.tsx`, `ProjectCard.tsx`)

Spine (type, cream base, layout, motion, structure) is identical across all 3 cards; only the accent color differs (+ eventually one signature motif per case study). Current assignments: AI Resume Score → twilight `#6B8CAE`, Go Social → coral `#E4674F`, Coins → purple `#8B6FC9`.

- **Panels:** each project in its own `rounded-3xl` panel, soft shadow, background = `linear-gradient(135deg, rgba(accent, 0.21), rgba(accent, 0.1))` layered over an explicit `var(--color-cream)` backing (blocks the aurora from bleeding through and muddying the accent — see Reusable technical rules). Stat number + "Read more" link use a `darken()`-ed (32%) version of the accent for text contrast; panels use the raw accent.
- **Phones:** transparent pre-cut PNGs (`Project.image` filename is decoupled from `slug`, e.g. AI Resume Score's file is `ai-resume.png`), `object-contain`, `filter: drop-shadow(...)` (not `box-shadow`) so the shadow follows the actual silhouette.
- **Signature interaction (all 3 cards):** desktop/fine-pointer-only 3D cursor-tilt (damped `useSpring` rotateX/rotateY, capped at 6°, resets on pointer-leave) + layered depth (phone sits on a real forward Z-plane via `transformStyle: preserve-3d`, floats further on hover) + stat count-up. All tunables at top of `ProjectCard.tsx`.
- **Replay-on-re-entry (shared by every card):** `useReplayOnReentry` (`src/lib/useReplayOnReentry.ts`) returns one incrementing `playToken` per card — 0 until it first scrolls comfortably into view (`amount: 0.5`), then +1 each time it re-enters after having FULLY left the viewport since the last play (a second, `amount: 0` check for "has it completely left" — re-arms it; prevents twitchy re-triggering from hovering near the edge). Works in either scroll direction. Never advances past 0 when `reduced` is true. The stat count-up restarts from 0 on every increment (`useEffect` keyed on `playToken`); AI Resume's screen-life overlay force-remounts (`key={playToken}`) so every play starts clean with no stale in-flight reverse-transition. Both fire together since they share one token.
- **Screen-life overlay** (`PhoneScreenLife` in `ProjectCard.tsx`, on AI Resume and Coins; not yet on Go Social): gleam sweep (2.4s) → hero-number glow bloom (starts 0.7s in, rises 1.6s to full, LINGERS at full ~0.35s, then eases down ~0.75s to its resting glow) → single gold sparkle (starts 1.6s in, soft 1.1s fade in/out), replaying with the shared token above. Timing is one shared set of constants used identically by every phone with this treatment — don't retune per-phone. The gleam, glow, and sparkle use a dedicated `EASE_IN_OUT` cubic-bezier local to this overlay — a deliberate, flagged exception to the site's "ease-out curves only" rule (see Motion principles), chosen so the sequence flows in and settles rather than snapping. Purely additive, never renders a number. Each phone gets its own `ScreenLifeConfig` (in `SCREEN_LIFE_BY_IMAGE`, keyed by `Project.image`): its wrapper locked to that PNG's own exact aspect ratio (AI Resume `aspect-[1190/984]`, Coins `aspect-[1280/998]`) so percentage-based overlay positions don't drift under `object-contain` letterboxing, its own screen/glow/sparkle coordinates measured against its own image, and its own gleam/glow color — AI Resume is white gleam + twilight glow (matching its blue UI), Coins is gold gleam + gold glow (its own "reward energy" gesture, per explicit brief) with the panel's purple accent tint left untouched. Add Go Social's own config the same way once wanted.

### About (`About.tsx`) — bento grid

Sits between Projects and Contact, on the shared cream/aurora background (no opaque section background — the site-wide aurora shows through and is meant to blend into the tiles' warm tints, unlike Projects' panels which deliberately block it). Deliberately carries NO photo — the hero cut-out already owns the face — so presence comes entirely from bold type, tile composition, and warm tinted depth, not animation or imagery. Superseded an earlier stacked/editorial layout (asymmetric statement + "How I work" row + footer-style credibility block) that read too much like a long scroll; the bento grid's whole point is that everything fits in roughly one view.

- **Grid:** 12-col CSS grid, `gap-[15px]`, `max-w-[1210px]` mx-auto. Tiles get their span via plain Tailwind `col-span-*`/`row-span-*` utilities gated behind a custom `min-[820px]:` breakpoint (below it every tile is `col-span-12`, full-width, stacking in source order — Statement → Proof → 3 principles → Toolkit → Human note). Above 820px: Statement (`col-span-8 row-span-2`) + Proof (`col-span-4 row-span-2`) fill row 1–2; three principle tiles (`col-span-4` each) auto-flow into row 3; Toolkit (`col-span-8`) + Human note (`col-span-4`) auto-flow into row 4 — no explicit `grid-row` needed, the spans alone make the auto-placement land correctly.
- **Tile shell (`.bento-tile` in `globals.css`):** shared by every tile — 26px radius, hairline border (defaults to `rgba(255,255,255,.55)`, overridden per themed tile), a layered shadow (inset top highlight + soft warm drop shadow), a `::before` top-sheen (top 40%, white-to-transparent) for a lit/tactile feel, and a fine-pointer-only hover lift (`translateY(-2px)` + deeper shadow, via `@media (hover: hover)`, not gated on reduced-motion since it's a discrete hover affordance like Contact's pill lift). Only each tile's own background gradient + border color vary, passed as plain string constants (same pattern as `ProjectCard`'s `panelTint`) — all deliberately warm (amber/coral/rose/terracotta/gold), no cool blue/purple, so the grid reads as one golden-hour family; separation comes from tint shade + border + depth, not hue temperature.
- **Content:** Statement tile (the anchor — "I build products that **earn their place** in people's lives.", `clamp(2.1rem,3.9vw,3.7rem)` Bricolage) + Proof tile (3 stacked stat/caption pairs) fill the top; 3 principle tiles (accent dash + bold title + one-liner, reusing the same three-accent idea as the old "How I work" row) fill the middle; Toolkit (skill pills, same tactile-pill construction as Contact's link chips) + a deliberately small/quiet Human note (gold sparkle + one line) close it out.
- **Motion — real bug hit and fixed here:** each tile is `motion.div` with `initial="hidden"` + `whileInView="visible"` (gentle per-tile stagger via incrementing `delay`). Tiles below the fold that never intersect the viewport got stuck at `opacity:0` even under `prefers-reduced-motion` — because `usePrefersReducedMotion()` reports `false` on the very first client render by design, and Framer Motion's `initial` pose, once resolved at that first (pre-correction) render, doesn't retroactively update just because the `variants` object reference changes later for a component that's still sitting in its untriggered `whileInView` state. Fixed by adding `animate={reduced ? "visible" : undefined}` — `animate` outranks `whileInView` in Framer's priority order, so it forces every tile to its final visible state the instant `reduced` corrects to `true`, regardless of scroll position or intersection. This is the Framer-Motion analog of the `useState`/`useSpring` "initial value only applies once" trap already in Reusable technical rules below — same root cause, different API.
- **Whitespace gotcha reused from the previous build:** the statement's coral `<span>earn their place</span>` needs `{" "}` explicitly on both sides — see Reusable technical rules.

### Contact — the closing section (`Contact.tsx`)

Currently the last section on the page (`About` will be inserted between Projects and this later — `page.tsx` has a placeholder comment marking the spot). This is the visual bookend to the hero: the hero opens the page in vivid golden-hour light, this section brings it back down into a warm sunset close. Light and warm throughout — never dark, unlike the originally-planned dark Contact (see Site rhythm above and Rejected approaches).

- **Background:** its own opaque vertical gradient (`SUNSET_GRADIENT`, `linear-gradient(to bottom, #F4EEE4 0%, #F3DDBE 55%, #EFBEA0 100%)`) — cream at the top continuing from whatever precedes it, deepening into a pale warm amber/coral "bright horizon" at the bottom. Deliberately much paler than the hero's full-saturation Vivid Sky. Like the hero, this section opts OUT of the shared ambient aurora (`AmbientBackground.tsx`) by keeping its own opaque background — aurora is for the in-between calm sections; hero and this closing section are the two dedicated-atmosphere bookends.
- **Living sunset:** two large, heavily-blurred warm blooms (amber, coral — `.sunset-bloom-drift-a/b` in `globals.css`) plus a low "sun" glow that drifts side to side and pulses in size/opacity (`.sunset-glow-drift`), all layered over the static gradient. Same transform-only drift technique as the site-wide aurora (translate + scale, GPU-friendly), tuned warmer AND — after a first pass that matched the aurora's own subtlety (3–4% translate, 16–20s) and read as static — deliberately more pronounced: ~9–12% translate, scale swinging ~0.86–1.28, opacity swinging ~0.45–1 on the sun-glow, 12/14/16s durations. This section is meant to be clearly noticed, unlike the aurora's "felt, not noticed" bar. Per-element opacity/size are tunables in `Contact.tsx` (`SUN_GLOW_*`, `SUNSET_BLOOM_*`, raised from their first-pass values too); durations/ranges live in the `globals.css` keyframes alongside the aurora's. Verified by sampling computed transforms over ~8s (not a still screenshot — confirmed tx/ty/scale/opacity all swing substantially) and by screenshotting three points across a cycle — text stays fully legible throughout. **Gotcha:** the sun-glow's centering (`left: 50%` + `translateX(-50%)`) is baked into its own keyframe rather than a separate static transform — under `prefers-reduced-motion`, disabling the animation would lose that centering entirely unless the class ALSO sets a static `transform: translateX(-50%)` fallback outside the keyframe (it does — don't remove it if this ever gets refactored).
- **Content, centered, generous spacing:** headline ("Let's build something people love.", ink, big Bricolage) → sub-line (muted, Hanken) → email as the primary CTA (`kumarishweta.email@gmail.com`, `mailto:`) → LinkedIn/GitHub/Download-CV as pill chips.
  - **Email:** a deep warm brown (`EMAIL_COLOR = "#7A2E1E"`) at rest, shifting to coral (`EMAIL_HOVER_COLOR`, matches `--color-coral`) on hover, plus a coral underline draw-in and a soft coral `text-shadow` bloom. Colors are set as `--email-color`/`--email-hover-color` CSS custom properties (consumed by `.email-cta`/`.email-cta:hover` in `globals.css`), NOT plain inline styles — an inline `style.color` can't respond to `:hover`, but a custom property consumed by a stylesheet rule can. The underline (`bg-current`) and hover glow automatically track whichever color is live.
  - **Links:** tactile pill chips (`LINK_PILL_CLASS` in `Contact.tsx`) — semi-transparent white over the sunset, a warm border derived from the same brown as the email, `backdrop-blur-sm`, small `currentColor` icon + label. Lift (`-translate-y-0.5`) + more-opaque background + soft warm shadow on hover.
- **Email wrapping gotcha:** a long email with no spaces is one unbreakable "word" — `break-all`/`break-words` picks an arbitrary character boundary on narrow screens (e.g. split "gmail.co" / "m"). Fixed by splitting the string into local-part/domain in JS and inserting a `<wbr />` between them, so the browser prefers breaking at the `@` and only falls back further if it still doesn't fit.
- **Footer bar:** slim, muted, static (not part of the scroll-reveal choreography — deliberately, per brief: "functional baseline, not a design moment"). © line, an optional repeated nav (Projects · About · Contact — all three anchors now resolve, since About shipped), and "Back to top ↑" (`href="#top"`, matching `<main id="top">` in `page.tsx`; works via the site-wide `scroll-behavior: smooth`, no JS needed).
- **Motion:** headline/sub-line/email/links reveal once on scroll-in (fade + rise, same `reveal()` shape as `Projects.tsx` — plain `whileInView`/`once: true`, NOT the replay-on-re-entry hook, since a one-time arrival moment doesn't need to replay every time you scroll past the footer and back). Background drift is separate and continuous (see Living sunset above), gated on the same `prefers-reduced-motion` check.

## Reusable technical rules

- **Measuring rendered text width:** use a DOM `Range` (`range.selectNodeContents(el)`) over the text node, not `el.getBoundingClientRect()` — a flex child without `items-start` stretches to fill its container, so its own bounding box isn't the actual glyph extent.
- **Absolutely-positioned children ignore a parent's padding** as an inset — use explicit `left-*`/`right-*`, not `left-0`/`right-0`, if the parent has padding.
- **A `position: fixed` background layer is invisible behind any section's own opaque background** — sections must have no opaque `background-color` to let it show through; this is normal CSS painting, not a stacking bug.
- **A semi-transparent panel over a transparent section picks up whatever is behind it.** If it needs a consistent look regardless of what's behind (e.g. the aurora), give it an explicit opaque backing color in the same `background` shorthand, not just its own tint alone.
- **`useState`/`useSpring` initial values only apply on the very first render.** Never seed one from `usePrefersReducedMotion()`'s value directly (`useState(reduced ? a : b)`) — it reports `false` on first paint by design and only corrects after hydration, so the initializer gets stuck on the wrong branch. Compute the reduced-motion value at render time instead, or correct it via a `useEffect` keyed on `reduced`.
- **Percentage-positioned overlay children need their image wrapper's aspect ratio locked to the source asset's exact ratio** (`aspect-[w/h]`) — otherwise `object-contain` letterboxes differently at every breakpoint and every percentage drifts.
- **Verifying "is this visible enough" requires actually looking** (screenshot/pixel sampling), not reasoning about opacity math. A layer can be technically non-zero but practically imperceptible; when that happens, suspect the *technique* (e.g. many small faint particles vs. a few large color blooms), not just the opacity value.
- **Playwright round-trip latency (evaluate calls, console.log, `scrollIntoViewIfNeeded`) can itself eat as much time as a short animation**, causing a naive "scroll → wait → screenshot" test to miss the whole window and look broken. Sample `getComputedStyle(...)` inside a single in-page `requestAnimationFrame` loop instead for ground truth.
- **Next dev's image-optimizer cache (`.next/dev/cache/images`) doesn't reliably invalidate when a `public/` file is swapped under a running server** — delete that directory and restart if a replaced image isn't showing up.
- **A JSXText child's leading/trailing whitespace is trimmed even when there's no line break** — whitespace sitting at the very start/end of a text node (i.e. touching a tag boundary) is unsafe, not just whitespace that crosses a line break. `<span>foo</span> bar` can silently render as "foobar." Wrap the space in its own expression container instead — `<span>foo</span>{" "}bar` — on every side of the tag that needs one.
- **A Framer Motion element using `initial`/`whileInView` + a `variants` object built from `usePrefersReducedMotion()` can get stuck invisible.** The hook reports `false` on the very first client render by design (see the `useState`/`useSpring` rule above), so `initial="hidden"` resolves against the WRONG (not-yet-reduced) variants at that first render. For an element that never satisfies `whileInView` (e.g. it's below the fold and the page never scrolls that far), Framer doesn't retroactively re-apply `hidden` once `variants` updates to the corrected (reduced) values — it just stays at whatever pose it first resolved to, i.e. genuinely invisible, even though `reduced` is now `true` and hidden/visible are supposed to be identical. Fix: add `animate={reduced ? "visible" : undefined}` — `animate` outranks `whileInView` in Framer's priority order, so it force-corrects the pose the instant `reduced` flips true, independent of scroll position. Same root cause as the `useState`/`useSpring` rule (a value that's wrong on first paint and only corrects after hydration), different API surface.
- **To force a `motion` animation to replay cleanly (not just re-trigger a boolean prop), remount via a `key` that increments each time it should play**, rather than toggling `animate` between two states — a fresh mount always starts from `initial` with no risk of catching a previous play's reverse-transition mid-flight. Relatedly: an effect shaped like `if (someDependency) { setSomeState(literalValue); }` — mirroring one signal directly into another piece of state — reliably trips the `react-hooks/set-state-in-effect` lint rule even when it's legitimate (e.g. resetting on exit before an unrelated later re-arm); restructuring so the state update is a functional counter increment (`setState(n => n + 1)`) in only one conditional branch, with other branches only touching refs, avoids it.

## Rejected approaches (don't retry without a strong reason)

- Dark "dusk" full-section treatment for Projects — fought the bright hero, dimmed the phones it was meant to showcase.
- Bebas Neue as the display face — shipped only weight 400, had to carry identity through size alone; replaced by Bricolage Grotesque.
- Ambient background as sparse embers + a faint glow alone — measured as imperceptible on cream even after one intensity bump; replaced by the Aurora (large color blooms) approach.
- Flat `rgba(accent, 0.1)` panel tint — read as invisible/plain grey; replaced by the two-stop gradient wash over a cream backing.
- Dark Contact/closing section — the original site-rhythm plan, dropped before ever being built once the dark-Projects failure made the pattern clear; Contact closes light/warm (a pale sunset gradient) instead.

## Working agreement

- This file is the source of truth. Reuse these tokens/patterns for new sections; don't introduce new ones without reason.
- Ritual scales with novelty: reusing an existing pattern (new project card, About/Contact using locked tokens) = build, self-check in browser, one-line note, minimal ceremony. Establishing a genuinely NEW pattern = verify properly and flag it. Mechanical tweaks (spacing, copy, constants) = no ritual.
- Self-verify by default: check your own work in the browser for visual/behavioral changes. Don't ask permission first and don't proactively share screenshots unless asked.
- Maintain this file yourself: add a one-line note under **Recent changes** for durable decisions (new token, convention, or shipped section/pattern); update the relevant architecture section above if something changed structurally. Skip logging for small tweaks.

## Verification discipline

- Verify once, visually/behaviorally, after finishing a section or a change flagged as visual/animation work — then conclude.
- Small mechanical edits (spacing, copy, color, constants, renames) need no screenshots/test scripts unless something could plausibly break.
- Typecheck (`tsc --noEmit`) + lint are the primary correctness gate for logic — don't add ad-hoc test scripts beyond that unless asked.
- If a verification result looks wrong, suspect the test/measurement method first, not the code. Don't spiral into repeated re-testing — state the uncertainty in one line and move on.
- One clean verification pass beats exhaustive re-confirmation.
